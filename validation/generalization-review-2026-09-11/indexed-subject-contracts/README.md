# Fixed investigations with structural subject contracts

The thirteen fixed investigation interfaces now connect their numeric rows to
complete mathematical subjects, actual operations or independently stated
conditions, and typed result values or workloads. Their source equations use
the shared finite derived-observation operation and functional subject maps.
Their comparison equations concern the same subjects. The scalar native
interfaces instantiate the subject operations; those native expressions have
one definition.

The exporter checks the actual basis calculation against the complete typed
observation application, its map-functionality theorem, and the observation
and comparison applications in the supplied corollaries. A theorem specialized
to a different Boolean argument is refused. Each bundle contains the full typed
propositions, subject-map expressions, reachable kernel definitions, and an
explicit list of constants supplied by the accepted Isabelle context. Candidate
and facet domains come from the checked basis definition. Runtime repair and
revision calls use that facet domain.

The final isolated context checks 20 changed or new theories and reuses 316
unchanged complete import contexts from the retained accepted 826-theory main
session. The five negative exporter controls cover unrelated equations, maps,
observation and comparison corollaries, and a differently specialized argument.
These controls and all thirteen owner registrations pass.

The baseline covers every facet subset for all thirteen interfaces, both
pattern-marker assignments, and one unavailable-facet control per family:
98 cases. The final proved code reproduces every complete original case,
result, profile, ordered loss table, repair, revision, and independent finite
assessment. The preceding accepted intermediate executions are retained too.
The ordinary command path also reproduces the collapsed-pattern report and a
probe report supplied with misleading descriptions. Their actual formal
contracts remain visible in their receipts. All 60 tooling tests pass.

Two prospective host investigations retain their complete structural inputs,
operations and outputs. One compares the complete returned assessment with
its public JSON representation; the existing JSON-copy operation is the only
eligible supplied operation on all 98 original cases. The other compares the
entire generated runtime programs under changes to registry descriptions and
facet dictionaries. Both generators preserve label changes in 98 cases; only
the structural generator also preserves all 98 programs after the dictionary
is reindexed. The complete initial and followed reports and their critical
assessments are retained. Their finite table evaluation is conditional on those
executed host observations and does not prove arbitrary Python semantics.

The failed proof attempts, original host serialization rejection, corrected
proposals, full source snapshots, original parent inputs, code exports, and
runtime artifacts are retained. The index identifies each proof, execution,
investigation and supporting attachment. The archive manifest checks stored
bytes; the subject equations establish what the fixed observations compute.
The two roles are separate.

This batch does not interpret the registry prose as a theorem, expand the
fixed candidate families, or implement native checking of mathematical proofs.
The latter remains under O-85, with the broader pending obligations unchanged.
