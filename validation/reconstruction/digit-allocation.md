# Persistent digit allocation

The closed digit store carries original environment formation and an actual
strict upper bound on every artifact-use head. Complete lookup equivalence
transfers the established original bound, freshness and update arguments.
Loading checks the original rows and derives the head once. Allocation checks
the new artifact, inserts at the stored next use and increments the head;
binding updates retain all original local guards and preserve that head.

The original optional result relation is factored independently at the complete
counter and original environment. The original and digit stores instantiate
it. An unavailable prepared input has no row; a failed operation on an available
input has one explicit absent-result row. The complete view includes the counter
and every artifact and binding, independently of the local update code.

A reusable source-case family supplies the original and digit APIs. Twelve
actual methods run on sixteen prepared cases. Both soundness and completeness
select the typed API and complete reference. Native execution compares all 192
original and digit candidate results for equality and retains both complete
families. All 40 original reports are exactly recovered. Three digit subject
serializations enumerate the same finite sets in a different order; these
presentations are retained alongside native equality, without host sorting.

Persistent chains after zero, 32 and 128 allocations retain 1, 33 and 129
artifacts and next heads 1, 33 and 129. Both traversals of the actual next digit
insertion take 5, 15 and 19 positions; the original unary traversals take 4, 36
and 132. The original None lookup still takes two positions. The instrumentation
is proved equal to the complete original insertion. These counts exclude key
construction, arithmetic, finite-value operations and complete-view reporting.
