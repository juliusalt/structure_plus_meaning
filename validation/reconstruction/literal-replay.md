# Admission of an actual literal replay

The independent condition requires an actual native replay that closes at the
given proof root and an actual application whose argument is the whole
requested artifact. The complete source, program and application sites, proof
root and requested payload precede every method decision.

The fixture starts with an actual empty native package, constructs an original
requirement decision for a literal artifact, and retains every returned
certificate and native replay. Its test requirement family is explicitly empty.
Every unavailable replay remains unavailable, and coverage requires an actually
returned valid original replay. The test policy does not establish adequate
requirements for a development workflow.

Seven methods run on seven complete cases. The 20 reports retain the full seed,
decision and keyed replay family, every subject, package and application
reading, every replay reading, and all computed conditions and revisions.
Native selection and adequacy retain methods 0 and 6. Their separate all-input
theorems establish equivalence to the original condition; method 6 uses the
existing uniqueness of actual application readings.

Removing proof material or changing its root leaves the package and application
readable while closed replay fails. Changing the requested payload preserves a
closed replay for the original payload, but fails literal agreement. Empty or
malformed environments yield no native readings. Prefixing use coordinates
with 300 preserves the valid reading, without imposing a byte restriction on
use words. An always-rejecting method satisfies soundness but fails completeness
on the two valid cases; the revision adds that missing condition.

```sh
python3 -B tools/reconstruct_literal_replay.py \
  --poly /opt/isabelle/contrib/polyml-5.9.2-2/x86_64_32-linux/poly \
  --output /tmp/literal-replay-reconstruction
```

The gate is shared with the proved replay-to-generation constructor. The
constructor's judgment quotation and the truth of the requested call remain
separate requirements. Arbitrary recorded-cause readers, complete workflow
policy and transitions, development-subject and criticism coverage, historical
permission, physical cost and genesis remain open.
