# Closed native development cycle

`native_development_packet` receives the original source and generator,
problem, condition sources and goals, native scope critic and initial
observation selection. It performs generation, requirement construction,
certified observations, independent evidence inspection and native criticism,
comparison and revision. Admission checks every required field against the
original question. An omitted phase cannot produce an admitted result.

Every admitted candidate has its original generator judgment and satisfies
every original native condition. Initial observation selections guide revision
without weakening these conditions. The scope critic reads the complete
question, ordered candidate family and all optional observation outputs;
separate evidence checks inspect all sources, answers and certificates.
A completed empty answer remains distinct from a failed required operation.

Ten actual producers run on eight complete questions. Controls drop phases,
certificates or generated occurrences, change the original question or critic,
or discard a repeated answer. Producer 0 alone is adequate on the full scope.
The comparison observes the original uncompiled goals independently. Its 101
records and the 24-record complete question roundtrip reproduce from source.
The cases retain duplicate answers, valid empty answers, unavailable or
refusing criticism, malformed input and nested conditions.

The original question reconstructs the local cycle without an accumulated
decision log. Broader scope adequacy, physical cost as source environments
grow, mathematical-proof admission, genesis and the final audit remain open.

Run `python -B tools/reconstruct_native_development.py --poly /opt/isabelle/contrib/polyml-5.9.2-2/x86_64_32-linux/poly --output /tmp/reconstruct-native-development --threads 16`.

`tools/run_native_development.py` also accepts `--question` through the proved
constructor; `tools/native_development_input.py` defines the complete input fields.

[Sources](native-development-sources.json), [reports](native-development-reports.json)
and [verification](native-development-verified.json) retain the reconstruction boundary.
