# Reconstruct judgments of actual native programs

The independent condition is the existing positive meaning of the complete
original program. Requested applications are constructed from its actual
clauses and requested terms. Each retains its clause key, complete binding
relation and every premise socket. The existing admitted-instance checker
checks material obligations and all call interfaces before a rule is returned.
An available application does not establish its conclusion.

`Factor_Finite_Program_Evaluation` checks three prerequisites: complete program
formation, coverage of every requested clause's variables by its head, and
closure of all generated premises within the finite demand. The coverage
theorem accounts for every original abstract instance of a requested call.
`Inference_Embeddings` and the existing closed-demand theorem connect the
unchanged finite inference evaluator to the original positive meaning.
Inference starts with an empty seed set.

Success returns exactly the positive calls in the requested family. Missing
head variables or an open demand return no answer, rather than negative
judgments. Coverage only constrains definitions that are actually requested;
an unrelated clause with hidden variables does not block a closed demand.
Malformed terms and absent definition sites can have valid negative answers
in a formed program. Program formation remains a separate input condition.

The investigation compares five actual operations: returning all possible
rule heads, returning one inference round, checked least closure, returning
every requested call, and always withholding an answer. Its conditions are
soundness, completeness and withholding an answer when the decision
prerequisites are absent. All observations and comparisons have proved
equations through complete program, demand, operation and condition maps.
The runtime contract reader checks that same operation and supplies its
candidate and facet domains.

The first execution used 17 subjects. It selected checked closure, but
independent criticism found that both material fixtures failed their check.
They used a payload as the empty enumeration terminator. The original material
definition requires the whole empty artifact. Those two rejected inputs remain
in the final family. `Factor_Finite_Material_Arguments` now constructs all five
operands from an actual artifact's complete rows, retaining occurrence anchors
and counted multiplicity. Its literal material pattern succeeds exactly when
that artifact is formed. Five added subjects include successful empty,
payload and incidence-bearing artifacts, an altered atom enumeration and
omitted incidence. All 17 original subject reports remain unchanged.

The expanded 22-subject comparison again selects only checked closure. Possible
rule heads wrongly establish unsupported cycles. One round misses conclusions
of a seeded cycle and a constructed larger argument. Returning every requested
call is unsound; always withholding an answer is incomplete. Starting with no
facets leaves 15 unresolved comparisons and produces 202 repair witnesses.
Starting with soundness alone leaves six unresolved comparisons and produces
26 witnesses. Both revisions select all three conditions. Reinvestigating
the returned selections leaves no residual comparisons; the complete initial
selection remains unchanged. The comparison covers these supplied operations
and workloads. The evaluator's exactness theorem has the broader stated
universal prerequisite boundary.

`Factor_Finite_Native_Evaluation` composes that selected operation with the
existing complete native package reader. It requires no supplied program model,
coordinate map or true seeds. Its answers use the recovered native coordinates.
`finite_native_program_evaluation_query` connects each successful requested
answer to entry 114 of the existing positive-query program on the complete
original environment value, selector, definition and term.

The 21 native inputs reuse actual source packages, compile the corrected
material subjects and reuse the four checked collection and pair installations.
Nineteen inputs produce answers, including the empty package; the absent
package and malformed environment produce no answer. The successful cases
contain 294 requested calls: 82 positive and 212 negative. The collection guard
accepts the empty collection under both original sources. The variable source
also accepts a collection containing an empty payload, while the equality
source rejects it. Their paired requirements retain that same distinction.
Every environment, recovered program, demand, generated application, rule and
answer is retained in the complete execution output.
