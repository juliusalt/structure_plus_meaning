# Reconstruct complete native proof nodes

The independently stated problem is constructing a fresh native node that
retains the original complete metadata and every part of the actual source.
The compiler receives the original environment, node form, clause and binding
family, and indexed proof-target family. Its universal contract is the original
`proof_node_code_for` condition. Local installation additionally requires every
target to exist in the source environment.

The construction shares complete term quotations, literal and citation
references, binding and discharge rows, table framing and record framing. The
existing abstract inference-node assembly is factored once and instantiated
by both the original existence proof and the finite compiler. A generic block
installer supplies a fresh use, complete reference recovery, source inclusion
and agreement at every old artifact and outgoing binding.

The investigation computes six independent conditions from each actual result:

1. Return a formed environment when the original prerequisites hold.
2. Recover the original node form, clause and complete bindings.
3. Recover the original complete indexed targets.
4. Preserve the entire original environment and its old readings.
5. Allocate a node use outside the original use family.
6. Refuse inputs whose original installation prerequisites fail.

The existing finite native reader supplies complete node readings. Its
uniqueness and a factored conjunction law ensure that the two metadata
inspections refer to one common reading. Candidate indices map to actual
constructor functions, problem indices map to complete structural inputs, and
the registered observation equation establishes each computed condition.

The first comparison executed eight methods on twenty-four inputs. It selected
only the complete constructor. A basis containing formation, preservation,
freshness and refusal reproduced that finite comparison, while omitting both
metadata conditions. Criticism exposed a candidate-scope weakness: the methods
that erased metadata also mishandled refusal on invalid original inputs.

Three additional methods first check the original prerequisites, then erase
bindings, erase targets or change the clause citation to another actual source
position. Two additional inputs exercise recursively paired whole and anchored
values and distinct values at different binding keys. Every original problem,
candidate result and assessment remains unchanged.

The expanded native calculation evaluates 1,716 condition positions, of which
1,476 hold. Only method 0 is selected and adequate. Fifteen inputs meet the
original installation prerequisites; the remaining eleven require refusal.
The former four-condition basis now has fifteen missing comparisons. Its 111
repair witnesses require the metadata conditions and produce
`[0,3,4,5,1,2]`, whose followed comparison has no residual. The complete basis
and the first run's returned basis `[5,3,0,1,2,4]` remain sufficient. Starting
with no conditions produces `[1,0,4,5,3,2]`. These are scoped sufficiency results;
no minimum-cardinality or arbitrary-method claim follows.

The complete report contains 26 original problems with all candidate returned
environments, 26 full assessment families, the scope, the comparison and four
revision cycles: 58 records. All original artifacts, bindings, node fields,
indexed targets, quotation values and position boundaries are retained.

With Isabelle and its matching Poly/ML executable, reconstruct from a fresh
output directory:

```sh
python3 -B tools/reconstruct_native_nodes.py \
  --poly /opt/isabelle/contrib/polyml-5.9.2-2/x86_64_32-linux/poly \
  --output /tmp/native-node-reconstruction
```

The [source boundary](native-nodes-sources.json) contains 382 files: 361 theories,
20 Python modules and the [complete-report comparison](native-nodes-reports.json).
The [verified reconstruction](native-nodes-verified.json) rebuilt the entire
closure from HOL, collected complete proof diagnostics with no errors, exported
the accepted code and reproduced every report field. Every original source and
execution input was verified. The [materialization receipt](native-nodes-materialization.json)
identifies the exact collected inputs. The complete 1,073-theory repository
check and all 98 host-tool tests also passed.

Fresh allocation is an explicit requirement of this local problem. Searching
for and reusing an existing matching node requires a separate comparison.
Reading metadata does not establish that the clause applies or its targets
prove the premises. [Source-derived certificates](native-derivations.md) and
[complete graph realization](native-graphs.md) have separate recipes. Joining
them into native proof placement and replay, native mathematical-proof checking,
development-cycle enforcement, the complete cost account, genesis and the final
repository audit remain open.
