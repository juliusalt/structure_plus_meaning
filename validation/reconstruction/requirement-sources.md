# Reconstruct source retention and native requirement installation

An equal source domain does not identify a program's meaning. Two complete
ordinary programs produce the same checked blueprint while their installed
guards give different results on the same empty payload. A second example
recovers actual native source and installed packages from complete artifacts:
the unchanged guard calls either equality or acceptance of every formed term,
depending on the original source clause.

`Factor_Retained_Clause_Admission` supplies ordinary entry 370. Its original
source environment and complete expected schema reference are fixed before
future candidates. Existing readers recover an actual package member, retain
every original artifact and binding, and check the complete variable-interface
single-clause definition. Its native compilation has the same all-term
contract. The finite implementation computes these conditions on both complete
environment tables and the actual recovered package.

`Factor_Requirement_Packages` instantiates the existing arbitrary-clause
constructor over the original native source package. It installs a fresh guard,
preserves all old interfaces and meanings, and leaves every original artifact
and outgoing binding unchanged. A common presentation theorem gives the actual
constructed package and clause an admitted complete operand. Conversely, an
independently admitted guard has the exact conjunction meaning against the
original source package, for every term.

Native package construction and its admitted presentation are established by
constructive totality theorems. The runtime executes finite package recovery,
source inclusion, complete-clause admission and the proved meaning observations.

The construction theorem preserves the original package's complete definition
domain inside its result. The general entry-370 checker checks the designated
clause within the recovered candidate package. It does not impose equality
between that whole package and one particular constructed extension. Inclusion
retains all original environment rows; it can permit additional rows. The
all-term source-meaning result consumes the actual original native package.

With Isabelle 2025-2 and Python 3.14, use fresh directories and a fresh session:

```sh
python3 -B tools/materialize_source_boundary.py \
  --manifest validation/reconstruction/requirement-sources-sources.json \
  --output /tmp/requirement-source-inputs
python3 -B /tmp/requirement-source-inputs/tools/reconstruct_requirement_sources.py \
  --poly /opt/isabelle/contrib/polyml-5.9.2-2/x86_64-linux/poly \
  --session Requirement_Source_Independent_Run \
  --output /tmp/requirement-source-results
```

The [manifest](requirement-sources-sources.json) contains only repository source
and the complete-report comparison. The common reconstruction runner rebuilds
the proof from HOL, recovers its full diagnostics, exports the accepted code,
and runs the three independent report families. Every stage must succeed and
every complete report must match [the comparison](requirement-sources-reports.json).
No saved proof, generated module or result log is an input. The optional
`--proof` mode reruns an accepted export and explicitly leaves reconstruction
of its proof and code unclaimed.

| Report family | Complete reports | Retained content |
|---|---:|---|
| Ordinary source boundary | 2 | Actual source choice, domain, complete checked plan, blueprint admission and installed guard result. |
| Native retained clauses | 15 | Both complete artifact and binding tables, every expected schema field, package root, selected entry, every recovered domain and all six computed conditions. |
| Native source meanings | 2 | Actual source choice, complete installed domain and guard result, with the observation equation derived from the all-term meaning theorem. |

The retention controls exercise an unchanged source, an extension, a changed
source carrier, wrong expected clauses, missing entries, wrong roots, an empty
candidate, malformed material, missing source artifacts and missing original
bindings. The final three controls keep the guard artifact unchanged. Replacing
its equality source with a variable clause fails under the original declared
source; independently declaring that variable source gives a different admitted
input. The native meaning reports establish the consequence of that source
change rather than accepting the unchanged domain as a semantic substitute.

The [verified run](requirement-sources-verified.json) and
[materialization receipt](requirement-sources-materialization.json) retain the
source-only reconstruction boundary. Comparison hashes identify reproduction
of all JSON fields, indices, ordering and repeated records. The
Isabelle-established contracts determine their meaning.

This is a contribution to the six conditions in `problems.txt`. The earlier
plan artifact still records a source domain. Joining every recursive plan and
original request to its actual native source and installed program remains
open, along with complete problem and approach selection, independent
criticism, workflow coverage, historical permission and the overall cost
account. The native checker does not authorize its own bootstrap handoff.
