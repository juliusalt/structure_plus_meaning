# Native selection installs a source and uses it

`native_source_development` takes the complete original policy questions and
source-change requests. Each request contains the original environment and
source selector, a finite family of complete target programs and entries, and
the subsequent query. No caller supplies satisfaction or installation flags.

The existing native dispatcher chooses the producer. That producer runs the
closed cycle on observations computed from the actual sources and programs:
source compatibility, entry membership, membership in the original target
family, and coverage by actual native generation. Each observation has a proved
equation to its independently stated original-subject condition.

Admitted indices map to complete targets. Repeated equal targets retain all
evidence occurrences and can determine one target value; distinct adequate
targets remain ambiguous. The selected target is installed, and the resulting
environment and entry become the actual source of the following query.
Final admission requires the complete original proposals, observations, native
execution, selected target, installation and query evidence.

The universal contract preserves every old artifact and binding and the entire
target meaning at the installed entry. Query answers are exactly the ordered
filter of the original output scope against the original target meaning,
including duplicate occurrences. A missing installation or query is refused.

The query interface preserves the existing total relation semantics. The
malformed-payload example completes with an empty answer; admission does not
separately assert that every original query term is well formed. This is
distinct from missing source, entry, installation or query evidence.

The full policy chooses producer 0. Normal installation, repeated equal targets,
the malformed-payload empty answer and the ordinary empty answer are admitted.
Distinct adequate targets, unreadable or incompatible sources, absent entries
and absent targets refuse the source change. Removing query evidence, the
installation or the original proposal scope also refuses admission.

The full, empty-policy and single-question runs retain 126, 17 and 29 complete
records. Reencoding both original input lists reproduces all 126 records.
A fresh shared 502-theory proof from HOL, without a supplied project parent,
reconstructs all 298 source-development records and the 280 existing steering
records. Every complete record directly matches its reviewed original run.
All 1,537 repository theories and 135 host tests pass, with 59 passing subtests
and two existing optional-dependency skips. The 48 other reconstruction
boundaries have unchanged inputs.

The original complete source run took about 20 minutes including output and
input verification, while other checks overlapped. The outer recipe permits
40 minutes per execution to include complete serialization and comparison.
These are validation timings, not evidence that practical-usefulness gate 5a
has been met.

Run `python -B tools/reconstruct_source_development.py --poly /opt/isabelle/contrib/polyml-5.9.2-2/x86_64_32-linux/poly --output /tmp/reconstruct-source-development --threads 16`.

`tools/check_source_development.py` accepts complete typed input lists through
`--questions` and `--requests`, together with `--proof`, `--poly`, `--project`
and a fresh `--output`. `--empty` and `--first` vary the policy scope while
retaining all requests. The input codec retains every program, clause, material
condition and original request field.

The finite target family remains an original input. This does not establish
general program discovery, practical usefulness on real development work,
historical permission, native mathematical-proof admission or genesis.
Condition 5a remains open; theoretical cost bounds under condition 5b are
deferred until after genesis. Isabelle retains its normative bootstrap role.
